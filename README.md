# oilcheck — автопроверка расчётов по эталонам на трёх слоях API

**Демо студии [TEMIRLAB](https://temirlab.com)** к задаче AstanaHub «Автопроверка расчётов нефтегазового ПО по эталонам на трёх слоях API». Пример отчёта: https://temirlab.com/demo/oil-autocheck/

Программа берёт набор эталонных сценариев, запускает каждый расчёт через тестовый API и сверяет числа в трёх местах:

1. **ответ расчёта** — результат задачи сразу после завершения;
2. **сохранённый результат** — повторное чтение кейса после сохранения;
3. **файл выгрузки** — CSV, XLSX или JSON, скачанный через API.

Для каждого поля и места свой допуск (абсолютный и/или относительный), для табличной выгрузки учитывается округление. Если число разошлось, в отчёте видно сценарий, место, поле, эталон, факт, дельту и **слой, на котором расхождение появилось впервые**: в формуле, при сохранении или при выгрузке.

Python 3.11+, только стандартная библиотека: ставить ничего не нужно, XLSX читается без openpyxl.

## Быстрый старт

```sh
sh demo.sh                                                   # Python 3.11+
docker run --rm -v "$PWD:/w" -w /w python:3.12-slim sh demo.sh   # или через Docker
```

`demo.sh` поднимает два релиза мок-API и делает три прогона:

| Прогон | Что происходит | Итог |
|---|---|---|
| Релиз 3.7.0 | эталонный продукт | 20 из 20 сценариев прошли |
| Релиз 3.8.0-rc1 | 4 регрессии в продукте, 5 % ответов API — 503, набор прогоняется дважды | 7 сценариев упали, у каждого указан слой, где появилась ошибка; ложных срабатываний нет |
| KPI | 300 отклонений внесено в продукт на разных слоях: выше допуска и ниже | выше допуска поймано 100 %, ниже допуска ложных срабатываний 0 |

Регрессии в 3.8.0-rc1 похожи на то, что бывает в жизни:

| Где | Ошибка | Что видно в отчёте |
|---|---|---|
| формула | в формуле Вогеля потерян квадрат (только если замер ниже Pнас) | IPR-03: разошлось уже в ответе расчёта, дальше во всех местах |
| сохранение | маппер пишет в итог только потери на трение, без гидростатики | PIPE-02, PIPE-04: ответ верный, сохранённый результат и выгрузка — нет |
| сохранение | при сохранении берётся плотность по умолчанию 0,85 | VOL-03: тяжёлая нефть 0,912 → тонны занижены |
| выгрузка | CSV пишется страницами по 36 строк, со второй страницы строки съезжают на одну | DCA-03, DCA-04: ответ и сохранение верные, в CSV с 37-го месяца сдвиг |
| выгрузка | в Excel рентный налог округлён до целых | ECO-02: только сценарий с экспортом |

Ещё в 3.8.0-rc1 сохранение пишет числа во float32 (шум около 1e-7). Это укладывается в допуски, и программа его не помечает.

## Команды

```sh
python -m oilcheck run --suite suites/demo --api api.toml --workers 8 --out reports
python -m oilcheck run --only "ECO-*" --repeat 2       # часть набора, дважды: проверка повторяемости
python -m oilcheck validate --suite suites/demo        # проверить формат набора без запуска
python -m oilcheck capture --suite suites/new          # черновик эталона с принятого релиза (проверяет инженер)
python -m oilcheck mutate --count 300 --mode api       # проверка KPI: внесённые отклонения ловятся
```

Код возврата: `0` — всё совпало, `1` — есть расхождения, `2` — ошибка выполнения (стенд недоступен, сломан формат). CI ориентируется на него.

Отчёты в `--out`:

- `report.html` — для QA и разработчика: сводка, матрица «сценарий × место», таблицы расхождений со значениями во всех трёх местах;
- `junit.xml` — для CI (GitLab, Jenkins, Azure DevOps, TeamCity, GitHub);
- `report.json` — всё то же для машин и истории прогонов;
- `summary.md` — короткая сводка; в GitHub Actions она сама попадает на страницу прогона.

## Как устроен набор

```
suites/demo/
  suite.toml              допуски, округление выгрузки, правила совпадения слоёв, формат выгрузки
  scenarios/IPR-01.toml   вход сценария
  scenarios/expected/IPR-01.json   эталон
```

Сценарий:

```toml
id = "ECO-02"
title = "Экономика: блок Б, экспорт 70 %"
calc = "economics"
export_format = "xlsx"
expected_file = "expected/ECO-02.json"

[input]
price_usd_bbl = 72
discount_rate = 0.12
# ...

# если эталон для какого-то места свой — переопределяем отдельные поля
[expected_layers.export]
"npv_musd" = 412.371

# если для сценария нужен свой допуск
[tolerance.fields]
irr_pct = { abs = 0.01 }
```

Допуски в `suite.toml`:

```toml
[tolerance]
default = { abs = 1e-6, rel = 1e-6 }       # |факт − эталон| ≤ max(abs, rel·|эталон|)

[tolerance.fields]
"*_musd" = { abs = 0.0005, rel = 1e-6 }    # шаблон по имени поля
"forecast[*].monthly_t" = { abs = 0.01 }   # конкретная колонка таблицы

[tolerance.layers.export]                  # отдельно для места проверки
"*_musd" = { abs = 0.001 }

[rounding.export]                          # знаков в выгрузке: + половина последнего разряда
"*_musd" = 3

[rules.saved_vs_response]                  # сохранение не должно менять результат
rel = 1e-6
[rules.export_vs_saved]                    # выгрузка может только округлять
rel = 1e-6
rounding = true
```

Таблицы сверяются по ключевой колонке (`year`, `month`, `pwf_atm`), а не по номеру строки, поэтому перестановка строк не даёт ложных ошибок, а пропуск или сдвиг строки ловится.

Новый сценарий — это новый файл в `scenarios/`, программу менять не нужно.

## Подключение к другому API

Шаги вызова описаны в `api.toml`: создать кейс, запустить расчёт, дождаться задачи, сохранить, перечитать, скачать выгрузку. Под стенд заказчика меняются адрес, авторизация, пути и поля ответа. Если API совсем нестандартный, можно указать `python_adapter = "модуль:Класс"` и описать вызовы кодом.

Токен берётся из переменной `OILCHECK_TOKEN`, адрес стенда можно переопределить через `OILCHECK_BASE_URL`. Повторы при 429/502/503/504 и обрывах настраиваются там же.

## CI

`.github/workflows/autocheck.yml` в этом репозитории: автотесты инструмента, прогон эталонного релиза, прогон релиза-кандидата с проверкой, что найдены именно внесённые регрессии и на своих слоях, и проверка KPI. Пример для GitLab — `ci/gitlab-ci.example.yml`.

## Что здесь демо, а что нет

- `mockapi/` — мок тестового стенда: пять упрощённых расчётов (индикаторная кривая, объёмный метод, падение добычи по Арпсу, потери давления в трубе, экономика с НДПИ, рентным налогом и КПН). Формулы правдоподобные, но это не методика заказчика.
- Эталоны демо-набора сняты с эталонного релиза мока командой `capture`. В пилоте эталоны и допуски даёт заказчик.
- `oilcheck/` — сам инструмент. Он не зависит от мока и подключается к любому HTTP/JSON API через `api.toml`.

Автотесты: `python -m unittest discover -s tests -v` (19 тестов, включая сквозные прогоны через мок).
